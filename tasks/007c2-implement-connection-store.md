# RFC-007c2: Implement bounded connection metadata storage

- Parent: [RFC-007](007-store-user-owned-connection-references.md), still incomplete.
- Status: done for bounded offline source after007c2a correction and independent CLEAR/APPROVE review. Actual PostgreSQL behavior awaits separate RFC-007c3 proof.
- Authority: coordinator explicitly accepted the 007c1 offline schema and `local evidence`, UTC epoch-millisecond DTOs/cursors, copied internal Uint8Array secrets, and assigned the five source/test paths below. No infrastructure, provider, credentials, environment, routes or composition authorized here.

## Exported consumer contract

`apps/server/src/modules/connections/store.ts` exports async `createConnectionStore(db: Pick<Database,"transaction">, options: unknown)`. Trusted options are strict `{configuration:{key,keyId},allowedProviders:string[],initializeEmpty:boolean}`. Keys stay in private closures. The factory verifies the key-check/nonce/count or explicitly bootstraps only an empty five-table store; it returns no service on failure. Provider identifiers are supplied by trusted adapter composition, copied, and never accepted as endpoint URLs.

Returned frozen methods: `createApiKey(actor,input)`, `replaceApiKey(actor,input)`, `revoke(actor,input)`, `listOwned(actor,input)`. Actors must be freshly issued by identity access, not deserialized/cast; each operation rechecks active membership under `FOR UPDATE`. Unknown/foreign resources use owner-scoped access with no admin bypass. Inputs are strict, secret bytes copied synchronously, labels preserve Unicode/whitespace while rejecting NUL, and expiry is a finite valid-Date UTC safe epoch integer/null. The public service has no plaintext resolver or native-profile method.

Mutations return `ConnectionMetadata` exactly `{id,kind,provider,label,state,revision,credentialVersion,createdAt,updatedAt,expiresAt,revokedAt}`. Dates are UTC epoch milliseconds, nullable where appropriate. Lists return immutable `{items,nextCursor}`, default 50/max100, UUID keyset order and bounded owner-bound domain-separated MAC cursor. No owner/key ID, MAC, ciphertext, secret suffix/length or private paths appear in DTOs. Replay returns original committed metadata, not readiness/current state.

`store-contract.ts` exports strict boundary parsers, metadata conversion, issued-actor guard, `ConnectionMetadata`, `Mutation` and fixed `ConnectionStoreError` codes. `store-keys.ts` is an internal module for exact ADR HKDF/HMAC and cursor encoding plus crypto sealing/key-check operations; it excludes `open`. No imports start a DB, server or infrastructure. Production composition remains unmodified.

Transaction design: membership → existing owner-scoped connection → key-check. Owner receipt match happens after membership but before stale revision/state/now-expired request checks. Separate DB-time read follows lock acquisition. Nonce reservation uses at most three fresh seals with `ON CONFLICT DO NOTHING`; successful metadata/version/nonce/count/receipt changes share one transaction. Replacement inserts the new credential before moving the current pointer; creation first supplies its FK parent. Revoke retains versions/tombstones and increments revision only. Factory initialization uses a domain-specific advisory transaction lock to serialize the absent-singleton case, then validates ledger count and key-check nonce. Count includes sentinel and caps at one million.

Unexpected mutation transaction rejection yields fixed `outcome-unknown`, with identical-operation retry as repair. It does not infer rollback or issue a fresh operation ID. No driver causes/SQL/request objects are attached to errors. Read failures are unavailable. Keys/configuration cannot be securely erased as JS strings; copied secret/temporary key buffers are cleared best-effort. Grant/readiness invalidation and dispatch-only secret consumption remain RFC-008/010 work; this slice must not be wired as completed execution readiness.
