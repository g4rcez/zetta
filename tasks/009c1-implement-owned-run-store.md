`createRunStore(db: Pick<Database,"transaction">)` is synchronous and returns four frozen async methods. Every method parses strict request syntax before verifying issued actor provenance, then uses a READ COMMITTED transaction with fresh active membership FOR UPDATE. Existing runs are queried by owner plus ID or owner plus request key; attempts by owner plus run plus generation/attempt ID, never attempt alone. Lock order remains membership→run→current attempt; historical result reads additionally lock the requested historical attempt after validating current projection. No administrator bypass exists.

Submit compares exact canonical text after validating the stored run/current attempt. New submission uses database millisecond clock after membership lock, generates both UUIDs, and inserts queued run+generation1 attempt atomically. Unique-conflict fallback re-reads the same owner/key; no second attempt is generated for a replay. Readiness/provenance of bot/conversation/configuration is still the trusted fixture producer's unresolved public-integration boundary. Unsupported harness/connections/resume are denied by the accepted parser.

Cancel locks the current rows, reads database clock after those locks, then calls accepted transitionRun and writes only the explicit mutable projections with owner/run/generation/revision predicates. Terminal cancellation and normalized terminal replay preserve original state. `applyRunTransition(tx, ownerUserId, token, fact)` is a separate trusted module export, absent from the owner store object. It re-locks/re-reads actual current rows and persists the accepted pure transition inside the caller's transaction. Caller must already hold fresh active membership and any earlier sorted connection locks and own commit/rollback. It supplies no backend observations, owner completion authority, claim loop or external IO.

`run-rows` validates exact actual-row shapes, finite Date instances before epoch conversion, canonical input correspondence with every immutable semantic column, owner/run/generation links, current run/attempt status and timestamp equality, full state and bounded result. Normalized run/attempt rows, parsed state/input/DTO and projection objects are readonly/frozen. Projection Date values are fresh local instances, not shared mutable state. Historical result validation uses the historical attempt's own lease/start/finish/stop/result/cancellation reason; it never manufactures an historical cancelRequestedAt from current run intent. The service first validates current rows before historical lookup. Queued/running valid results produce fixed `RunStoreError("result_pending")`; missing/foreign run or attempt produces `not_found`. Corrupt rows return `RunBoundaryError("storage_unavailable")`.

RunStoreError codes are `not_found`, `request_conflict`, `result_pending`, `outcome_unknown`; accepted RunBoundaryError/AccessError codes remain intact. Unexpected transaction rejection on submit/cancel maps to outcome_unknown without cause; identical submit key or owner read is the repair mechanism. Unexpected reads map to storage_unavailable. No raw SQL, driver cause, owner, lease or private input enters safe DTOs/errors.
