# RFC-009c4: Trusted cancellation before admission

Status: accepted after [coordinator independent review](../docs/reviews/no-admission-cancellation-009c4-review.md),2026-10-22. Owns run-state.ts, run-state.test.ts, run-rows.test.ts and this task/evidence only. No schema, row-parser production, store, claim, authority or DB changes.

Implements the required pure fact from [dispatch claim store](../docs/decisions/dispatch-claim-store.md): closed `{type:"cancelled_before_admission",atMs}`. A new transition requires current running, leased, no_effect, no startedAt/result/stop; existing identity, CAS, chronology and int32 revision guards apply. It yields cancelled/no_effect, finishedAt=atMs, null result and unchanged null stop, preserving lease/claim and existing owner intent or leaving owner intent absent for a backend cause. It never invents owner-request provenance or observed resource stop. Lease expiry does not prevent terminal cleanup; it confers no fresh execution permission.

Matching terminal replay requires cancelled/no_effect, retained lease, no start/result/stop. It preserves first finish/revision/intent and follows existing terminal replay order: closed event/token syntax and exact run/attempt/generation/lease before semantic match, then returns original state before stale expectedRevision/time/counter checks. Different identity or terminal semantics fail. A later stop fact prevents this specific semantic replay. Existing completion/loss/owner-cancel paths remain unchanged.

Inspected existing run SQL constraints and actual readRunRows/runProjection: their cancelled/no_effect/null-result/leased shape already supports this outcome, with or without owner intent. Round-trip tests use those actual implementations and historical result read. No outside-scope production change was required.

The pure fact is **not proof of safe cancellation**. A future trusted service must lock membership→run→attempt→claim→grants and prove exact current identity plus durable absence of prepare intent, receipt, pending operation, grants/admission or possible resource/action startup. This implementation creates no issuer or public route, makes no claim cleanup/capacity mutation and proves no actual SQL transaction. Caller booleans cannot substitute for that future locked history proof.

Tests cover closed syntax, queued/effect/stop/terminal conflicts, malformed state, stale identity/revision, chronology, finite integer time, MAX revision, replay and projection/readback.
