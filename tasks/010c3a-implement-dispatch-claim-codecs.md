# RFC-010c3a: Pure dispatch launch and claim row codecs

Status: accepted after [coordinator independent review](../docs/reviews/dispatch-claim-codecs-010c3a-review.md), 2026-10-22. Parent010 remains incomplete. Scope is four new runtime source/test files; accepted schema, migrations, identity and run foundations remain unchanged.

Implements the [accepted claim-store design](../docs/decisions/dispatch-claim-store.md)'s pure codec slice. `canonicalDispatchLaunchSpec(unknown)` and `decodeDispatchLaunchSpec(unknown)` preserve008's exact ten-element canonical tuple and digest. Historical parsing deliberately has no current clock admission check. `readDispatchClaim(raw, current, rawPolicy)` consumes the actual `ReturnType<typeof readRunRows>`, validates every current claim column, closed pairs/states/counters/finite times, initial revision shape, exact current owner/run/attempt/generation/lease/claimedAt, policy/image/digests and fixture budget mapping. Output is frozen `{claim, spec}` with Date values normalized to integer milliseconds. Invalid claim data throws a fixed `DispatchClaimRowsError` message `invalid_claim`, without raw causes or private input.

The parser is an internal structural read, not a public DTO or authority. Future005 activation revision and009 producer tuple are absent from current schema and are not manufactured. Membership, original operation request comparison, provenance, freshness, real locks, capacity and resource settlement remain caller/service obligations. Single-row parsing cannot establish OLD/NEW monotonic history, unique operation ownership, actual cleanup provenance or an authenticated launcher fact. Released rows require coherent terminal current state and retained cleanup facts; this validates structure only. No automatic launch, grant, bootstrap, cancel or DB operation is implemented.

Verification: red-first missing-module failures retained; final Bun focused/regression run62 tests/279 assertions passed, scoped strict TypeScript exit0 and all four LSP diagnostics clean. A test independently hashes literal canonical bytes using node:crypto and checks existing008 digest equality; substitutions and recomputed-hash corruption cannot bypass current-row checks. Tests include Unicode, byte/identifier/numeric boundaries, nullable/state/time controls, expired historical reads, repeated-read stability and frozen outputs. No DB or native execution was performed or claimed.
